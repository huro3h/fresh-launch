# fresh-launch

Chrome系ブラウザを **「起動前に最新化」してから開く** ための単独スクリプト。
利用中に右上へ出る「更新して再起動」を避けるのが目的。

## 背景・仕組み

Chromeの更新実体は **Chrome Updater（Omaha 4 / 旧Keystoneの後継）** が **ディスク上のアプリ本体を
更新**する処理で、「再起動」は起動中プロセスを新本体に差し替えるだけ。
つまり **ブラウザを閉じている間に更新を当ててから起動すれば、あの再起動UIは出ない。**

`fresh-launch` は、対象ブラウザが停止中のときにオンデマンド更新を当て、完了を待ってから
`open` する。起動中のときは（起動中の更新は再起動UIの原因になるため）更新せず状態を表示する。

更新には `GoogleUpdater --update-apps` を使う。これは**同期実行**（全登録アプリの処理を終えてから
終了する）で、定期チェックのスロットルを経由しないため**毎回実際にチェックが走る**。
アプリごとの結果を標準出力に出すので、対象チャンネルが本当にチェックされたかを確認したうえで
報告している（確認できなければ「最新」とは言わず「更新状態は不明」と表示する）。

## 使い方

```sh
# 状態だけ確認（何も変更しない・開かない）
./fresh-launch.sh status dev

# 最新化してから起動（停止中なら更新→完了待ち→open）
./fresh-launch.sh dev

# 実行内容を表示するだけ（更新もopenもしない）
./fresh-launch.sh --dry-run dev
```

`channel` は `stable | beta | dev | canary`、または `"Google Chrome Dev"` 等のフルアプリ名。

### オプション

| オプション | 説明 |
|---|---|
| `--status` / `status` | 更新保留の有無だけ表示（変更なし・開かない） |
| `--dry-run` | 実行内容を表示するだけ（更新も open もしない） |
| `--no-open` | 更新は当てるが起動はしない |
| `--force` | 他チャンネルが起動中でも更新を実行する（既定はスキップ） |
| `--timeout N` | 更新完了待ちの上限秒（既定 600） |
| `-h`, `--help` | ヘルプ |

## 状態判定の仕組み

- **ディスク上の最新** = `…/*.framework/Versions/Current` が指す版
- **起動中の版** = 起動中プロセスが実際にロードしている Framework 版（`lsof` で取得）
- **再起動保留あり** = 「起動中の版 ≠ Current」（＝新版がディスクに載っているのに古い版で動作中）

## 注意・制約

- **対象は Chrome系（Google Updater管理）のみ**。Brave等（Sparkle方式）は非対応（ガードで弾く）。
- **更新は全チャンネル一括**。特定チャンネルだけの更新はできない。
  → **他のChromeチャンネルを開いたまま実行すると、そちら側に「更新して再起動」が出てしまう**。
  そのため他チャンネルの起動を検出したら **既定では更新をスキップ**する（`--force` で上書き可）。
  最も確実なのは **Chrome系をすべて閉じている状態で実行**すること。
- 実際に更新を当てる処理はソフトウェアの状態変更。ユーザー権限のアップデータで動く（管理者権限不要）。
- **`GoogleUpdater --update` は叩かないこと**。アプリの更新ではなく**アップデータ自身**のセットアップで、
  実行するとユーザー側の自動更新を壊す（復旧は Google Chrome を普通に起動するだけでよい）。
  このスクリプトが使うのは `--update-apps` の方。

## 起動導線への紐づけ（例）

`open` の代わりにこのスクリプトを呼ぶようにする:

- シェルの alias（例 `alias chromed='~/projects/fresh-launch/fresh-launch.sh dev'`）
- Raycast / Alfred のスクリプトコマンド
- macOS「ショートカット」
- Dockアイコンを小さなラッパー.appに差し替え
